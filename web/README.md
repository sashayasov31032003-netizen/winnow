# Winnow: веб-приложение

> Раньше проект назывался StatLab: сменилось только имя. База переименована в
> `web/winnow.db` (данные перенесены), настройки стали `WINNOW_*`, cookie — тоже
> с новым именем, поэтому войти нужно заново. Наборы прежнего формата
> `.stldata` открываются по-прежнему.

Веб-версия Winnow: тот же движок статистики, что в настольной программе, но
работает в браузере. Статистика, чтение файлов, отчёты и выгрузки не переписаны
заново - они лежат в `src/winnow` и не зависят от Qt. Веб-слой только
добавляет вход, хранение наборов и HTTP.

## Быстрый старт

Из папки проекта (из любой другой папки — полным путём к `web\run.cmd`):

```powershell
# 1. сервер (окно держать открытым)
web\run.cmd

# 2. открыть приложение в браузере
web\open.cmd
```

Адрес приложения: <http://127.0.0.1:8000/>. Документация API для программистов:
<http://127.0.0.1:8000/docs>.

Сайт начинается с главной страницы: что это за платформа и два пути — «Создать
опрос» или «Исследовать данные». Дальше человек попадает на рабочее место.

| Адрес | Что это |
|---|---|
| `/` | главная: рассказ о платформе и выбор «создать опрос» / «исследовать данные» |
| `/app` | рабочее место: опросы и данные (нужен вход) |
| `/s/<slug>` | публичная анкета — без входа, по ссылке из опроса |
| `/docs` | документация API |

Первая установка окружения (один раз):

```powershell
python -m venv --system-site-packages web\.venv
web\.venv\Scripts\python -m pip install -r web\requirements.txt
```

`--system-site-packages` нужен, чтобы веб-версия видела numpy, pandas и scipy,
уже установленные для движка: переустанавливать их не нужно.

## Как устроено

```
src/winnow/web/          сервер
  core.py                 настройки, модели базы, подключение
  security.py             пароли (scrypt), подписанная cookie сессии
  storage.py              файлы наборов, страницы таблицы, правка ячеек
  surveys.py              опросы: структура, проверка ответов, лимит частоты
  survey_dataset.py       опрос → набор: вопрос = переменная, ответы = строки
  policy.py               какие процедуры разрешены API и ИИ (один список)
  api.py                  HTTP-эндпоинты
  ai_api.py               ИИ: чат потоком (SSE), диалоги, сохранённые расчёты
  ai/                     Research Intelligence
    agent.py              цикл: модель → инструмент → результат → ответ
    tools.py              9 инструментов поверх движка (только чтение)
    provider.py           OpenAI-совместимые провайдеры (Yandex, VseGPT, Ollama) и fake
    store.py              диалоги, вызовы инструментов, analysis_runs
    guardrails.py         проверка аргументов, чисел в ответе, квоты
    config.py             модель, резервные модели, лимиты, политика данных
  charts_svg.py           рисование графиков в SVG на сервере
  main.py                 сборка приложения, отдача интерфейса и /s/<slug>
  __main__.py             запуск: python -m winnow.web
src/winnow/analysis/
  quality.py              инспектор качества: данные и линейная модель
web/frontend/             React + TypeScript + Vite
  src/ResearchAI.tsx      раздел «Исследование AI»: чат и карточки расчётов
  src/QualityPanel.tsx    вкладка «Качество»: проблемы, метрики, переменные
  src/SurveysView.tsx     мои опросы, конструктор, ответы
  src/PublicForm.tsx      публичная форма /s/<slug>
  src/surveyAnswers.ts    значения полей и проверка обязательных
web/tests/                тесты API, ИИ и качества (127)
web/run.cmd, open.cmd     запуск и открытие
```

Ключевые решения:

* **движок общий.** Формы процедур строятся по тем же описаниям
  (`ui/procedure_specs.py`), что окна настольной версии, поэтому проверки и
  разбор полей совпадают. Новая процедура появляется в вебе без правки фронтенда.
* **графики рисует сервер** в SVG (`charts_svg.py`) из данных `stats/charts.py`.
  Так формулы живут в одном месте, а картинка одинаково выглядит в интерфейсе
  и в выгрузке.
* **отчёты собирает движок** (`export/html.py`), веб только отдаёт готовый HTML.
* **фронтенд собирается в `dist`** и отдаётся тем же сервером: один адрес, нет
  CORS, cookie сессии работает без настроек.
* **ИИ — серверный цикл с инструментами** (`ai/agent.py`): модель просит вызов,
  сервер выполняет его через тот же движок, а числа сохраняются в `analysis_runs`.
  Так ключ не попадает в браузер, а ответ можно проверить по `run_id`.

## Графики

Форма показывает только те поля, которые нужны выбранному виду:

| Вид | Что выбрать | Что показывает |
|---|---|---|
| Гистограмма | одну числовую переменную | распределение и частоты интервалов |
| Ящик с усами | числовую переменную; категорию — по желанию | один ящик или по ящику на каждую группу категории |
| Диаграмма рассеяния | две числовые переменные | точки, линию регрессии и r |
| Столбчатая / круговая | только категорию | частоты категорий; числовая переменная не нужна |
| Линия средних | числовую переменную и категорию | среднее и стандартную ошибку по группам |

Раньше поле «Категории» показывалось для всех видов, а у ящика с усами
игнорировалось. Теперь категория у ящика действительно группирует данные, а у
гистограммы и рассеяния лишние поля скрыты.

У `/run` и `/export` есть необязательные поля `split_by` (считать по группам) и
`weight` (веса случаев). Они действуют **на текущий расчёт** и не сохраняются в
набор: иначе включённое однажды разбиение незаметно меняло бы все следующие
отчёты.

## Безопасность

* пароли - `hashlib.scrypt` со солью, сравнение за постоянное время;
* сессия - подписанная HMAC-SHA256 cookie `winnow_session`, `httponly`,
  `samesite=lax`; токенов в localStorage нет намеренно (их крадут скриптом);
* чужой набор отвечает **404**, а не 403: иначе можно узнать, что он существует;
* неверный пароль и несуществующий адрес дают одинаковый ответ;
* правка данных принимает только существующие строки и переменные, значение
  приводится к типу переменной;
* через API **не запускаются** «Вычислить переменную» и «Перекодировать»: они
  считают присланные извне выражения, а выполнять чужой код на сервере нельзя,
  пока выражения не проверены отдельно.

### Research Intelligence

* **ключ модели хранится только в окружении сервера** (`WINNOW_AI_KEY`); клиент
  получает имя модели и остаток квоты, но не ключ;
* **ИИ не выполняет код и не ходит в базу напрямую**: только 9 инструментов,
  которые вызывают те же процедуры, что и кнопки интерфейса;
* **исходные данные не меняются**: инструменты работают на чтение; удаление и
  правка недоступны;
* **по умолчанию модели уходят схема, профиль и агрегаты**, строки — только при
  флаге набора и общем разрешении сервера (`WINNOW_AI_ALLOW_TEXT`);
* **числа в ответе сверяются с расчётами**: неподтверждённые попадают в
  предупреждение, а таблицы интерфейс берёт из сохранённого `run_id`;
* **дневная квота** сообщений на пользователя и аудит вызовов в `ai_tool_calls`.

### Опросы

Публичный опрос намеренно не требует входа: иначе его не пройти человеку,
которому Winnow не нужен. Вместо входа — то, что не мешает заполнять:

* **случайная ссылка** `/s/<slug>` (11 символов): чужой опрос перебором не найти;
* **один ответ с браузера**: случайный номер в cookie `winnow_respondent`, без
  аккаунта и без IP. Повторы включаются настройкой опроса;
* **ограничение частоты** ответов: не больше `WINNOW_SURVEY_RATE` в час с
  одного адреса (счётчик в памяти, сам адрес никуда не пишется);
* **закрытие** вручную или по дате; черновик по ссылке **не открывается**;
* ответы пишутся в таблицы `responses` и `answers` (`value_number`,
  `value_text`, `option_ids`), поэтому распределения считаются запросом, а не
  разбором JSON;
* структура опроса **фиксируется после первого ответа**: иначе старые ответы
  потеряли бы смысл (до этого момента конструктор свободно переписывает вопросы);
* опрос с ответами **не удаляется** — удаление стёрло бы чужие заполненные анкеты.

### Опрос → набор

Кнопка **«Исследовать в Winnow»** собирает из ответов обычный набор — без выгрузки
в CSV и без повторной загрузки файла:

| Вопрос в опросе | Переменная в наборе |
|---|---|
| один вариант | «Ваш пол» — категория с метками вариантов (1 = «Мужской») |
| несколько вариантов | «Источники: Радио», «Источники: ТВ», … — отметки 1/0 |
| число | «Возраст» — количественная |
| шкала | «Оцените курс» — порядковая |
| текст | «Что улучшить» — строковая, номинальная |

Имя переменной — текст вопроса: в «Данных» видно, о чём столбец; два одинаковых
вопроса получают номер. Пропуск остаётся пропуском (для множественного выбора —
не ноль, иначе «не спрашивали» и «не выбрал» смешались бы). Набор кэшируется:
повторное нажатие пересобирает **тот же** набор, а не создаёт копию; правки,
сделанные в наборе вручную, заменяются свежими ответами — источник здесь опрос.
Дальше это обычный набор: советчик, процедуры, графики, выгрузки. В `.sav` имена
транслитерируются (SPSS не принимает кириллицу в именах), полный текст остаётся
в метке; CSV и Excel сохраняют русские имена как есть.

## Настройки

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `WINNOW_DB_URL` | SQLite в `web/winnow.db` | на сервере: `postgresql+psycopg://user:pass@host/winnow` |
| `WINNOW_DATA` | `web/data` | где лежат файлы наборов |
| `WINNOW_SECRET` | девелоперский | **на сервере обязательно заменить** |
| `WINNOW_INVITE_ONLY` | `1` | `0` - свободная регистрация |
| `WINNOW_SESSION_DAYS` | `30` | срок жизни сессии |
| `WINNOW_MAX_UPLOAD` | 50 МБ | предел размера файла |
| `WINNOW_SURVEY_RATE` | `30` | сколько ответов на опрос принимается с адреса за час |
| `WINNOW_CORS` | адреса Vite | откуда фронтенду разрешено обращаться |
| `WINNOW_AI_PROVIDER` | `fake` без ключа | `fake`, `yandex`, `vsegpt`, `ollama`, `deepseek`, `openrouter`, `custom` |
| `WINNOW_AI_KEY` | — | ключ модели, **только на сервере** (также `OPENROUTER_API_KEY`, `WINNOW_OPENROUTER_API_KEY`, `YANDEX_API_KEY`, `VSEGPT_API_KEY`) |
| `WINNOW_AI_MODEL` | `dots-studio/dots-3-note-preview:free` у OpenRouter | модель; для Yandex — `gpt://<каталог>/<модель>/latest` |
| `WINNOW_AI_FOLDER_ID` | — | каталог Yandex Cloud |
| `WINNOW_AI_BASE_URL`, `WINNOW_AI_AUTH_SCHEME` | по пресету | адрес и схема авторизации (`Bearer` / `Api-Key`) |
| `WINNOW_AI_TOOL_FALLBACK` | `1` | повтор без tools, если модель их не умеет (ответ без расчётов) |
| `WINNOW_AI_DAILY_TURNS` | `20` | сообщений агенту на пользователя в сутки |
| `WINNOW_AI_ALLOW_TEXT` | `1` | `0` — запретить сырые строки всем наборам |
| `WINNOW_HOST`, `WINNOW_PORT` | `127.0.0.1`, `8000` | куда слушать |
| `WINNOW_OPEN_BROWSER` | `1` | `0` - не открывать браузер |

Из России проще всего **Yandex AI Studio** (Alice AI Flash, рубли, ключ
`Api-Key`) или **VseGPT** (OpenAI-совместимый агрегатор, без VPN); совсем
бесплатно — локальный **Ollama**. OpenRouter из РФ обычно недоступен. Подробные
примеры — в `docs/research-intelligence.md`.

Для запуска с моделью есть готовые файлы: `web\run-vsegpt.cmd` (спросит ключ и
не сохранит его), `web\run-openrouter.cmd` (то же для OpenRouter) и
`web\run-ollama.cmd` (локально, без ключа).

**OpenRouter.** В `run-openrouter.cmd` модель —
`dots-studio/dots-3-note-preview:free`: она поддерживает tools.
`deepseek/deepseek-r1:free` OpenRouter больше не обслуживает (404 «no provider
serves this model»). Если endpoint не поддерживает `tools`, сервер повторяет
запрос без инструментов и предупреждает, что ответ без расчётов.

## Оформление

Интерфейс собран на одной системе токенов в `web/frontend/src/styles.css`:
палитра, шкала отступов 4/8/12/16/24/32/48, радиусы, тени и тайминги. Тёмная и
светлая темы — только разные значения переменных, компоненты общие.

| Принцип | Как сделано |
|---|---|
| Иерархия типографикой и воздухом | мало рамок, заголовки 20–24 px, служебный текст 11,5–13 px |
| Цвет — сигнал, а не украшение | зелёный/жёлтый/красный только для состояния; уровни измерения различаются тоном |
| Слово важнее цвета | статус опроса — точка **и** подпись, а не только цвет |
| Числа читаются | табличные цифры в таблицах, правый край для числовых колонок |
| Контраст по AA | основной текст и подписи не ниже 4,5:1 в обеих темах |
| Клавиатура | видимый фокус `:focus-visible`, цели не меньше 44×44 в анкете |
| Движение уважает систему | `prefers-reduced-motion` отключает анимации |
| Тема по системе | первый визит следует `prefers-color-scheme`, выбор запоминается |

Проверка вёрстки без ручного браузера: `build\shots.py` снимает экраны через
Chrome DevTools (включая вход по cookie, светлую тему и мобильную ширину).
Скриншоты складываются в `build/shots/`.

## Переносимая веб-версия

Версия без Python и без установки: сервер, интерфейс и движок в одном каталоге
(или одном файле). Собирается скриптом:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_web_portable.ps1
```

Что получается в `dist-web`:

| Файл | Что это |
|---|---|
| `Winnow-web\` | каталог: запускается быстрее, данные лежат рядом в `web\` |
| `Winnow-web.exe` | один файл: проще передать, при запуске распаковывается во временную папку |
| `Winnow-web-portable.zip` | архив каталога с `README.txt` и запусками для AI (~83 МБ) |

В архиве рядом с exe лежат `OpenRouter.cmd`, `VseGPT.cmd` и `Ollama.cmd`: они
спрашивают ключ (кроме Ollama) и не сохраняют его. OpenRouter из России часто
отвечает `403 Access denied by security policy` — это блокировка сети/региона,
а не ключ; в этом случае используйте VseGPT или Ollama. Если VPN работает в
браузере/Python, но не в exe, добавьте `Winnow-web.exe` в VPN или запускайте
VseGPT/Ollama.

Данные (база, опросы, ответы, наборы) лежат в папке `web\` рядом с exe, поэтому
переносить нужно папку целиком. Настройки — те же `WINNOW_*`, что и у обычного
запуска. Если однофайловая версия пишет «Could not create temporary directory»,
задайте `TMP` и `TEMP` на доступную папку — об этом же сказано в `README.txt`
внутри архива.

Перед сборкой нужен собранный интерфейс (`cd web\frontend; npm.cmd run build`):
скрипт проверяет это и напоминает, если `dist` нет.

## Разработка интерфейса

```powershell
cd web\frontend
npm.cmd install
npm.cmd run dev     # интерфейс на :5173, запросы /api идут на :8000
npm.cmd run build   # собрать в dist, его отдаёт сервер
```

## Перед публикацией

1. Свой `WINNOW_SECRET` и HTTPS (иначе cookie сессии уйдёт открытым текстом).
2. PostgreSQL вместо SQLite.
3. Миграции схемы: сейчас `create_all` плюс `schema_version` для колонок; при
   переходе на PostgreSQL понадобится Alembic.
4. Право выдавать приглашения - только администратору; сейчас может любой вошедший.
5. Ограничение частоты попыток входа (защита от перебора паролей).
6. Политика обработки персональных данных: в наборах лежат ответы людей.
7. Ключ ИИ на сервере, платный endpoint с политикой «не обучаться» для реальных
   данных и общий счётчик квоты при нескольких рабочих процессах.
8. Резервные копии базы и папки с наборами.

## Известные ограничения

* **Автоматических тестов интерфейса нет** - вёрстка проверяется сборкой,
  `oxlint` и скриншотами (`build\shots.py`). Ошибку вроде «отчёт не там, где
  смотришь», по-прежнему ловит только человек.
* **Веса поддержаны не всеми процедурами.** Учитываются в частотах,
  описательных, сопряжённости, t-критерии, корреляциях Пирсона, ANOVA и
  линейной регрессии - последние три сверены с SPSS (F = 392,824; R2 = 0,913;
  r = 0,954 при N = 22, см. `docs/weights-reference.md`). Остальные процедуры
  веса не учитывают и честно об этом предупреждают в отчёте.
* **Импорт опроса** из аналога Google Forms не сделан: ждёт согласованного формата.
* **Сводки по вопросам внутри опроса нет.** Данные анализируются в «Данных» на
  наборе, собранном кнопкой «Исследовать в Winnow»; распределения прямо на
  экране опроса — этап 3 (см. `docs/surveys.md`).
* **Ограничение частоты — в памяти процесса.** При нескольких рабочих процессах
  лимит умножится на их число: понадобится общий счётчик (Redis).
* **Research Intelligence — Фазы 0–1.** Агент считает и объясняет, инспектор
  проверяет качество данных и линейной модели. Ещё не сделаны поиск
  закономерностей, сравнение моделей и многорасчётные отчёты (см.
  `docs/research-intelligence.md`, `docs/quality-inspector.md`).
  Ответ приходит целиком, без потоковых токенов; бесплатные модели имеют суточный
  лимит и могут обучаться на промптах — для реальных данных нужен свой endpoint.
