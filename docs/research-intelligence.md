# Research Intelligence 1.0

Модуль, который помогает пройти путь от данных до вывода: агент понимает
вопрос словами, смотрит схему и профиль набора, выбирает статистический метод,
запускает **реальный расчёт** в ядре Winnow и объясняет результат.

Главный принцип: **ИИ не считает статистику**. Все коэффициенты, p-value, R²,
доверительные интервалы и размеры выборки приходят из результата процедуры,
который сохранён в `analysis_runs`. Модель решает, что и как считать, но не
подставляет числа.

## Состояние: Фазы 0–1

Готово и покрыто тестами (27 тестов ИИ и 9 тестов инспектора + прежние 438
движка и 127 API):

| Часть | Что сделано |
|---|---|
| Расчёты | результат любой разрешённой процедуры сохраняется в `analysis_runs` и доступен по `run_id` |
| Инструменты | 9 инструментов: схемы, профиль, качество, список процедур и их форм, запуск процедуры, сценарии советчика, сохранённый расчёт, фрагмент строк, список наборов |
| Качество данных | инспектор: пропуски, дубликаты, выбросы, дисбаланс групп, корреляции, VIF, Бреуш-Пеган, Дарбин-Уотсон, Кук, нормальность остатков; вкладка «Качество» |
| Агент | серверный цикл с tool-calling, максимум 6 шагов, финальный вызов без инструментов, отмена по разрыву соединения |
| Поток | SSE: `start`, `tool_call`, `run`, `tool_result`, `warning`, `text`, `done`, `error` |
| Проверка чисел | числа в ответе сверяются с результатами расчётов; неподтверждённые помечаются предупреждением |
| Интерфейс | раздел «Исследование AI»: выбор набора, чат, карточки вызовов и расчётов с таблицами |
| Доступ к данным | по умолчанию — только схема, профиль и агрегаты; строки — по флагу набора |
| Квоты и аудит | дневной лимит сообщений, `ai_tool_calls` с аргументами, статусом и длительностью |
| Миграции | `schema_version` и идемпотентное добавление колонок в существующую базу |

## Архитектура

```
Браузер (раздел «Исследование AI»)
   │  POST /api/ai/chat  → SSE
   ▼
ai_api.py  — права, квоты, поток
   ▼
ai/agent.py — цикл: модель → вызов → результат → модель
   ├── ai/provider.py — ChatProvider: OpenAI-совместимые API и fake
   ├── ai/tools.py    — инструменты, только чтение
   ├── ai/guardrails.py — схемы аргументов, проверка чисел
   └── ai/store.py    — диалоги, вызовы, расчёты
                        │
                        ▼
                 DIALOG_SPECS.build → engine.execute → Result
                        │
                        └── analysis_runs (JSON результата)
```

Почему цикл на сервере, а не в браузере: ключ не покидает сервер, инструменты
выполняются в доверенной среде, каждый вызов попадает в аудит, а числа можно
проверить. Почему не LangChain и подобное: цикл занимает ~200 строк, а лишняя
зависимость усложнила бы сборку и отладку.

### Провайдеры

`ChatProvider` — один метод `complete(messages, tools)`. Реализации:

- `OpenAICompatibleProvider` — общий HTTP-клиент для OpenRouter, VseGPT,
  Yandex AI Studio, DeepSeek, Ollama и любого совместимого endpoint'а; умеет
  `Bearer` и `Api-Key`, перебирает основную и резервные модели, объясняет ошибки;
- `FakeProvider` — детерминированные ответы для тестов и демо-режима без ключа.

Смена провайдера — переменные окружения, не правка кода.

### Провайдеры, доступные из России

| Провайдер | API | Инструменты | Оплата | Ограничения |
|---|---|---|---|---|
| **Yandex AI Studio** (Alice AI LLM / Flash) | OpenAI-совместимый `/v1/chat/completions` | `tools` + `tool_choice` | рубли, карты РФ и СБП; Alice AI Flash — 0,1 ₽ / 0,2 ₽ за 1 000 токенов | нужен каталог (`folder_id`) и ключ; бесплатного тарифа нет, но у Yandex Cloud бывает стартовый грант |
| **VseGPT** | OpenAI-совместимый `/v1` | `tools` у моделей с бейджем | 199 ₽ за 30 дней + стоимость токенов; бесплатный тестовый период | без VPN; 1 запрос/сек; агрегатор, а не первоисточник |
| **GigaChat** (Сбер) | свой API, OAuth, `functions`/`function_call` | вызов функций (legacy-формат) | 365 млн токенов freemium для действующих клиентов; новые клиенты с 01.09.2026 — через cloud.ru | нужен отдельный адаптер, в этой версии не подключён |
| **Ollama** (локально) | OpenAI-совместимый `/v1` | `tools` у Qwen3, Llama 3.1+ и подобных | бесплатно | нужен компьютер с 8–16 ГБ RAM; качество ниже облачных моделей, зато данные не уходят |
| **DeepSeek** напрямую | OpenAI-совместимый | `tools` | дешево, но иностранная оплата | доступность и оплата из РФ не гарантированы |
| **OpenRouter** | OpenAI-совместимый | `tools` у платных endpoint'ов; у `:free` часто нет | бесплатные модели с лимитом | из РФ без VPN обычно недоступен; `deepseek-r1:free` часто не умеет tools |

**Про Алису.** Приложение «Алиса» бесплатно, но публичного API «Алисы» для
сторонних приложений нет. Программируемый доступ — это Yandex AI Studio с
моделями **Alice AI LLM** и **Alice AI Flash**; он платный (цены выше), оплата
российскими картами, данные клиентов не используются для обучения, логирование
можно отключить заголовком `x-data-logging-enabled: false`.

Примеры включения (ключи — только на сервере):

```powershell
# Yandex AI Studio: Alice AI Flash. model можно не задавать — соберётся из каталога
set WINNOW_AI_PROVIDER=yandex
set WINNOW_AI_KEY=<API-Key>
set WINNOW_AI_FOLDER_ID=<идентификатор каталога>
set WINNOW_AI_MODEL=gpt://<каталог>/aliceai-llm-flash/latest

# VseGPT: агрегатор, работает без VPN
set WINNOW_AI_PROVIDER=vsegpt
set WINNOW_AI_KEY=<ключ VseGPT>
set WINNOW_AI_MODEL=openai/gpt-4o-mini

# Ollama: совсем бесплатно и локально, модель должна уметь tools
set WINNOW_AI_PROVIDER=ollama
set WINNOW_AI_MODEL=qwen3:8b
```

### OpenRouter: что работает сейчас

OpenRouter подключён как обычный OpenAI-совместимый провайдер; ключ читается из
`OPENROUTER_API_KEY` (или `WINNOW_AI_KEY` / `WINNOW_OPENROUTER_API_KEY`):

```powershell
web\run-openrouter.cmd     # спросит ключ и не сохранит его
# или вручную:
set OPENROUTER_API_KEY=<ключ>
set WINNOW_AI_PROVIDER=openrouter
set WINNOW_AI_MODEL=dots-studio/dots-3-note-preview:free
web\run.cmd
```

**Проверено с VPN и реальным ключом.** OpenRouter отвечает, ключ принят.
`deepseek/deepseek-r1:free` больше не обслуживается: на любой запрос приходит
`404 no provider serves this model anymore`. Бесплатных моделей DeepSeek в
каталоге сейчас нет. Из доступных free-моделей с инструментами проверена
`dots-studio/dots-3-note-preview:free`: она вызвала `get_dataset_schema`,
`get_profile` и `run_procedure`, расчёт сохранился как `run_id`, ответ пришёл
по-русски. Она и стоит по умолчанию. Часть моделей (`xingchen-agi/...`,
`google/gemma-4-31b-it:free`) в момент проверки отвечала `429 upstream
rate-limited` — это ограничение провайдера, а не ключ.

**Важное ограничение.** Бесплатные `:free`-endpoint'ы OpenRouter часто не
поддерживают нативный вызов инструментов: запрос с `tools` возвращает
`404 No endpoints found that support tool use`. Поэтому при такой ошибке
провайдер повторяет запрос **без инструментов**, а ответ помечается
предупреждением «без расчётов»: числам из него доверять нельзя. Для реальных
расчётов нужна модель/endpoint с поддержкой tools (dots, платный DeepSeek или
VseGPT/Yandex). Отключить повтор можно `WINNOW_AI_TOOL_FALLBACK=0`.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `WINNOW_AI_PROVIDER` | `fake`, если нет ключа; иначе `openrouter` | `fake`, `yandex`, `vsegpt`, `ollama`, `deepseek`, `openrouter`, `custom` |
| `WINNOW_AI_KEY` | — | ключ провайдера, только на сервере; принимаются также `OPENROUTER_API_KEY`, `WINNOW_OPENROUTER_API_KEY`, `YANDEX_API_KEY`, `VSEGPT_API_KEY`, `DEEPSEEK_API_KEY` |
| `WINNOW_AI_MODEL` | `dots-studio/dots-3-note-preview:free` у OpenRouter | модель; для Yandex — `gpt://<каталог>/<модель>/latest` |
| `WINNOW_AI_FOLDER_ID` | — | каталог Yandex Cloud (можно `YANDEX_FOLDER_ID`) |
| `WINNOW_AI_BASE_URL` | адрес пресета | совместимый endpoint; для `custom` обязателен |
| `WINNOW_AI_AUTH_SCHEME` | `Bearer` / `Api-Key` у Yandex | как подписывать ключ |
| `WINNOW_AI_PROJECT` | каталог у Yandex | заголовок `OpenAI-Project` |
| `WINNOW_AI_TOOL_FALLBACK` | `1` | повтор без tools для моделей, которые их не умеют |
| `WINNOW_AI_FALLBACKS` | бесплатные модели OpenRouter | резерв через запятую |
| `WINNOW_AI_MAX_STEPS` | 6 | вызовов модели за ход |
| `WINNOW_AI_MAX_TOKENS` | 1400 | предел ответа модели |
| `WINNOW_AI_DAILY_TURNS` | 20 | сообщений на пользователя в сутки |
| `WINNOW_AI_ALLOW_TEXT` | 1 | общий запрет сырых строк, если 0 |

Бесплатные модели OpenRouter подходят для разработки и демонстраций: лимит
примерно 50 запросов в день, один провайдер на endpoint, часть endpoint'ов
может обучаться на промптах. Для реальных данных с персональными сведениями
нужен платный endpoint с политикой «не обучаться» или локальная модель.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `list_datasets` | список наборов |
| `get_dataset_schema` | переменные, метки, типы, уровни, коды пропусков |
| `get_profile` | роли, пропуски, выбросы, нормальность, пригодность групп |
| `check_quality` | качество данных и линейной модели; сохраняет `run_id` |
| `get_preview` | до 20 строк — только при разрешении набора |
| `list_procedures` | список процедур или поля формы конкретной |
| `run_procedure` | расчёт через движок, сохранение `run_id` |
| `suggest_research` | сценарии советчика |
| `get_run` | сохранённый расчёт; предупреждает, если данные изменились |

Запрещено: SQL, произвольный код, `compute`/`recode`, правка и удаление данных,
чужие наборы. Список разрешённых процедур — `web/policy.py`, один для API и ИИ.

## Проверка чисел и риски

1. Модель видит только результаты инструментов; в промпте прямо запрещено
   считать самостоятельно.
2. Финальный текст сверяется с числами из результатов; расхождение даёт
   предупреждение в интерфейсе. Это эвристика с допуском по числу знаков после
   запятой: «0,03» может означать 0,031, а «99,5» не будет принято за 100.
3. Интерфейс показывает таблицы из сохранённого расчёта, а не из текста модели.
4. Данные, метки и текстовые ответы считаются данными, а не инструкциями.
5. Исходные данные неизменны: ИИ работает только на чтение.

Ограничения Фазы 0, о которых нужно помнить:

- поток отдаёт события, но не отдельные токены: ответ приходит целиком;
- нет поиска закономерностей, сравнения моделей, What-if и графа — это
  следующие фазы;
- нет потокового отображения рассуждений и «плана» агента;
- SQLite и один процесс: квота считается по сообщениям в базе, при нескольких
  воркерах нужен общий счётчик;
- в тестах модель не вызывается: проверяется наш цикл, а не чужой API;
- **DeepSeek R1 free больше не обслуживается OpenRouter**; рабочая free-модель
  по умолчанию — `dots-studio/dots-3-note-preview:free`, остальные free-модели
  могут отвечать 429 из-за лимитов провайдера;
- OpenRouter может быть недоступен по сети из РФ — это ограничение сети, а не
  ключа; тогда нужен VseGPT, Yandex AI Studio или локальная модель;
- история диалогов сохраняется в базе, но экран пока не восстанавливает прошлый
  диалог: каждое открытие раздела — новый разговор.

## Как запустить и проверить

```powershell
# Демо без ключа: агент отвечает, что модель не подключена
set WINNOW_AI_PROVIDER=fake
web\run.cmd

# Yandex AI Studio (Alice AI Flash), оплата в рублях
set WINNOW_AI_PROVIDER=yandex
set WINNOW_AI_KEY=<API-Key>
set WINNOW_AI_FOLDER_ID=<каталог>
web\run.cmd

# VseGPT — OpenAI-совместимый агрегатор без VPN
set WINNOW_AI_PROVIDER=vsegpt
set WINNOW_AI_KEY=<ключ>
web\run.cmd

# DeepSeek напрямую
set WINNOW_AI_PROVIDER=deepseek
set WINNOW_AI_KEY=<ключ>
web\run.cmd

# OpenRouter (если доступен из вашего региона)
set WINNOW_AI_PROVIDER=openrouter
set WINNOW_AI_KEY=sk-or-...
web\run.cmd
```

Проверки:

```powershell
python -m pytest web\tests -q     # 127 тестов API, ИИ и качества
python -m pytest -q               # 438 тестов движка
```

## Дальше по плану

**Сделано:** Фаза 0 (агент и расчёты) и Фаза 1 (Quality Inspector,
см. `docs/quality-inspector.md`).

1. **Discovery Engine** — систематический поиск связей и различий с поправкой
   FDR и проверкой устойчивости.
2. **Model Arena** — сравнение линейной/логистической моделей и бейзлайнов,
   затем при необходимости деревья и бустинг.
3. **What-if Lab** — сценарии на сохранённой модели без изменения данных.
4. **Research Graph** и **Research Reports** — граф связей и отчёт из нескольких
   расчётов с интерпретацией.

Каждая фаза должна сохранять главное правило: числа — из расчёта, ссылка — на
`run_id`, данные — без изменений.
