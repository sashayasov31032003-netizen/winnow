# Research Intelligence 1.0

Модуль, который помогает пройти путь от данных до вывода: агент понимает
вопрос словами, смотрит схему и профиль набора, выбирает статистический метод,
запускает **реальный расчёт** в ядре Winnow и объясняет результат.

Главный принцип: **ИИ не считает статистику**. Все коэффициенты, p-value, R²,
доверительные интервалы и размеры выборки приходят из результата процедуры,
который сохранён в `analysis_runs`. Модель решает, что и как считать, но не
подставляет числа.

## Состояние: Фаза 0

Готово и покрыто тестами (16 тестов ИИ + прежние 434 движка и 105 API):

| Часть | Что сделано |
|---|---|
| Расчёты | результат любой разрешённой процедуры сохраняется в `analysis_runs` и доступен по `run_id` |
| Инструменты | 8 инструментов: схемы, профиль, список процедур и их форм, запуск процедуры, сценарии советчика, сохранённый расчёт, фрагмент строк, список наборов |
| Агент | серверный цикл с tool-calling, максимум 6 шагов, финальный вызов без инструментов, отмена по разрыву соединения |
| Поток | SSE: `start`, `tool_call`, `run`, `tool_result`, `warning`, `text`, `done`, `error` |
| Проверка чисел | числа в ответе сверяются с результатами расчётов; неподтверждённые помечаются предупреждением |
| Интерфейс | раздел «Исследование AI»: выбор набора, чат, карточки вызовов и расчётов с таблицами |
| Доступ к данным | по умолчанию — только схема, профиль и агрегаты; строки — по флагу набора |
| Квоты и аудит | дневной лимит сообщений, `ai_tool_calls` с аргументами, статусом и длительностью |
| Миграции | `schema_version` и идемпотентное добавление колонок в существующую базу |

## Архитектура

```
Браузер (раздел «Исследование AI»)
   │  POST /api/ai/chat  → SSE
   ▼
ai_api.py  — права, квоты, поток
   ▼
ai/agent.py — цикл: модель → вызов → результат → модель
   ├── ai/provider.py — ChatProvider: OpenRouter / fake
   ├── ai/tools.py    — инструменты, только чтение
   ├── ai/guardrails.py — схемы аргументов, проверка чисел
   └── ai/store.py    — диалоги, вызовы, расчёты
                        │
                        ▼
                 DIALOG_SPECS.build → engine.execute → Result
                        │
                        └── analysis_runs (JSON результата)
```

Почему цикл на сервере, а не в браузере: ключ не покидает сервер, инструменты
выполняются в доверенной среде, каждый вызов попадает в аудит, а числа можно
проверить. Почему не LangChain и подобное: цикл занимает ~200 строк, а лишняя
зависимость усложнила бы сборку и отладку.

### Провайдеры

`ChatProvider` — один метод `complete(messages, tools)`. Реализации:

- `OpenRouterProvider` — OpenAI-совместимый HTTP, перебор основной и резервных
  моделей при 429/5xx/404, понятные ошибки;
- `FakeProvider` — детерминированные ответы для тестов и демо-режима без ключа.

Смена провайдера — переменные окружения, не правка кода. Локальный сервер
(Ollama/vLLM) подключается тем же OpenAI-совместимым путём.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `WINNOW_AI_PROVIDER` | `fake`, если нет ключа; иначе `openrouter` | провайдер |
| `WINNOW_AI_KEY` (или `WINNOW_OPENROUTER_API_KEY`) | — | ключ, только на сервере |
| `WINNOW_AI_MODEL` | `xingchen-agi/xing4.0-29b-a4b:free` | основная модель |
| `WINNOW_AI_FALLBACKS` | две бесплатные модели | резерв через запятую |
| `WINNOW_AI_BASE_URL` | `https://openrouter.ai/api/v1` | совместимый endpoint |
| `WINNOW_AI_MAX_STEPS` | 6 | вызовов модели за ход |
| `WINNOW_AI_MAX_TOKENS` | 1400 | предел ответа модели |
| `WINNOW_AI_DAILY_TURNS` | 20 | сообщений на пользователя в сутки |
| `WINNOW_AI_ALLOW_TEXT` | 1 | общий запрет сырых строк, если 0 |

Бесплатные модели подходят для разработки и демонстраций: лимит примерно
50 запросов в день, один провайдер на endpoint, часть endpoint'ов может
обучаться на промптах. Для реальных данных с персональными сведениями нужен
платный endpoint с политикой «не обучаться» или локальная модель.

## Инструменты

| Инструмент | Что делает |
|---|---|
| `list_datasets` | список наборов |
| `get_dataset_schema` | переменные, метки, типы, уровни, коды пропусков |
| `get_profile` | роли, пропуски, выбросы, нормальность, пригодность групп |
| `get_preview` | до 20 строк — только при разрешении набора |
| `list_procedures` | список процедур или поля формы конкретной |
| `run_procedure` | расчёт через движок, сохранение `run_id` |
| `suggest_research` | сценарии советчика |
| `get_run` | сохранённый расчёт; предупреждает, если данные изменились |

Запрещено: SQL, произвольный код, `compute`/`recode`, правка и удаление данных,
чужие наборы. Список разрешённых процедур — `web/policy.py`, один для API и ИИ.

## Проверка чисел и риски

1. Модель видит только результаты инструментов; в промпте прямо запрещено
   считать самостоятельно.
2. Финальный текст сверяется с числами из результатов; расхождение даёт
   предупреждение в интерфейсе. Это эвристика с допуском по числу знаков после
   запятой: «0,03» может означать 0,031, а «99,5» не будет принято за 100.
3. Интерфейс показывает таблицы из сохранённого расчёта, а не из текста модели.
4. Данные, метки и текстовые ответы считаются данными, а не инструкциями.
5. Исходные данные неизменны: ИИ работает только на чтение.

Ограничения Фазы 0, о которых нужно помнить:

- поток отдаёт события, но не отдельные токены: ответ приходит целиком;
- нет поиска закономерностей, сравнения моделей, What-if и графа — это
  следующие фазы;
- нет потокового отображения рассуждений и «плана» агента;
- SQLite и один процесс: квота считается по сообщениям в базе, при нескольких
  воркерах нужен общий счётчик;
- в тестах модель не вызывается: проверяется наш цикл, а не чужой API.

## Как запустить и проверить

```powershell
# Демо без ключа: агент отвечает, что модель не подключена
set WINNOW_AI_PROVIDER=fake
web\run.cmd

# С ключом OpenRouter
set WINNOW_AI_KEY=sk-or-...
set WINNOW_AI_MODEL=xingchen-agi/xing4.0-29b-a4b:free
web\run.cmd
```

Проверки:

```powershell
python -m pytest web\tests -q     # 105 тестов API и ИИ
python -m pytest -q               # 434 теста движка
```

## Дальше по плану

1. **Quality Inspector** — пропуски и их паттерны, дубликаты, выбросы,
   мультиколлинеарность, гетероскедастичность, влиятельные наблюдения.
2. **Discovery Engine** — систематический поиск связей и различий с поправкой
   FDR и проверкой устойчивости.
3. **Model Arena** — сравнение линейной/логистической моделей и бейзлайнов,
   затем при необходимости деревья и бустинг.
4. **What-if Lab** — сценарии на сохранённой модели без изменения данных.
5. **Research Graph** и **Research Reports** — граф связей и отчёт из нескольких
   расчётов с интерпретацией.

Каждая фаза должна сохранять главное правило: числа — из расчёта, ссылка — на
`run_id`, данные — без изменений.
