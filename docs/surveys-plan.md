# План: свой сайт с опросами и анализом

> **Этапы 1–2 сделаны.** Что собрано, какие решения приняты и как это проверить —
> `docs/surveys.md`.

Цель: один сайт с двумя функциями — создать опрос и провести исследование по его
результатам. Своя реализация, без зависимости от системы коллеги.

## Почему это хорошая идея технически

Сейчас в Winnow данные приходят «снаружи» (CSV/Excel/SAV), и программе приходится
угадывать уровни измерения по значениям: где категория, где шкала, где вопрос с
несколькими ответами. Отсюда предупреждения в советчике и ручные проверки.

Если опрос создаётся у нас, **вся структура известна заранее**: тип вопроса,
варианты, обязательность. Значит переменные получают правильные метки и уровни
измерения без догадок, а множественные ответы сразу хранятся как отметки 1/0 —
без разбора строк и без риска ошибки.

## Новое: сбор ответов

### Модель данных

```
Survey      id, owner_id, title, description, status(draft/open/closed),
            slug, created_at, closes_at, allow_multiple
Question    id, survey_id, position, kind, text, required, options(json)
Response    id, survey_id, submitted_at, respondent_token, meta(json)
Answer      id, response_id, question_id, value_text, value_number, option_ids(json)
```

Отдельная таблица `Answer` (а не JSON целиком) — чтобы можно было считать
распределения запросом, а не разбором JSON в памяти.

### Типы вопросов (минимальный набор)

| Тип | Как попадает в набор |
|---|---|
| один вариант (`single`) | категория с метками вариантов |
| несколько вариантов (`multi`) | отметки 1/0 по каждому варианту |
| число (`number`) | числовая переменная, шкала |
| шкала 1..5 (`scale`) | порядковая переменная |
| текст (`text`) | строковая переменная |

### Экраны

1. **Мои опросы** — список со статусом и числом ответов, кнопка «Создать».
2. **Конструктор** — вопросы, варианты, обязательность, порядок, предпросмотр.
3. **Публичная форма** `/s/<slug>` — без входа, адаптив, проверка обязательных.
4. **Результаты** — сводка по вопросам и кнопка **«Исследовать в Winnow»**:
   опрос превращается в набор, открывается советчик.

## Ключевые решения

1. **Одно приложение, не два сервиса.** Опросы и анализ живут в одном FastAPI:
   меньше движущихся частей, вход общий, набор создаётся сразу в памяти.
2. **Ответы в базе, не в файлах.** Отчёты сохраняются мгновенно, опрос можно
   закрыть, а данные не пропадут при перезапуске (в отличие от бесплатных
   хостингов с эфемерным диском).
3. **Публичная ссылка без входа** — иначе опрос не пройти. Защита: случайный
   `slug`, ограничение частоты, один ответ на браузер (cookie + токен), закрытие
   по дате и вручную.
4. **«Исследовать в Winnow»** не копирует данные: набор строится из ответов и
   кэшируется как обычный набор — дальше работает всё, что уже написано.

## Риски и как их снимаем

| Риск | Решение |
|---|---|
| Наводнение ответами, спам | случайный slug, ограничение частоты, закрытие опроса |
| Двойные ответы | токен в cookie + отметка в базе; при `allow_multiple=false` — отказ |
| Удаление опроса с ответами | подтверждение и мягкое удаление (архив) |
| Персональные данные | предупреждение в конструкторе, поле «анонимный опрос» |
| Долгие ответы (текст) | ограничение длины, обрезка в отчёте |
| Опрос изменён после ответов | правка структуры запрещена после первого ответа, только закрытие |

## Порядок работы

**Этап 1. Сбор (без анализа).** Модели, конструктор, публичная форма, сохранение
ответов, список опросов. Проверка: пройти опрос самому, ответ появился в базе.

**Этап 2. Превращение в набор.** Опрос → `Dataset` с правильными именами,
метками и уровнями измерения; кнопка «Исследовать в Winnow». Проверка: советчик
предлагает осмысленные исследования, отчёт считается.

**Этап 3. Удобства.** Статусы и закрытие, экспорт CSV, число ответов, сводка по
вопросам, множественные ответы отметками.

**Этап 4. По желанию.** Шаблоны опросов, обязательные вопросы, ветвление,
ограничение по времени прохождения, QR-код ссылки.

## Открытые вопросы (нужно решить до кода)

1. Заполнять опрос может **кто угодно по ссылке** или только приглашённые?
2. Один ответ с человека или **несколько** (например, оценка преподавателя разными
   студентами)?
3. Нужны ли **анонимные** опросы (без привязки к аккаунту респондента)?
4. Хранить ли IP и время прохождения (нужно для защиты от накрутки, но это
   персональные данные)?
5. Должен ли сайт работать и как «просто формы», без анализа — то есть можно ли
   отдать ссылку человеку, которому Winnow не нужен?
