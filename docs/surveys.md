# Опросы: сбор ответов и превращение в набор

Сделаны этапы 1 и 2 плана `docs/surveys-plan.md`: опрос создаётся и проходит по
ссылке без входа, а его ответы одной кнопкой превращаются в обычный набор
Winnow, на котором работает вся статистика.

Проверка этапа 1: опрос открывается по ссылке `/s/<slug>` без входа, ответ
сохраняется в базе. Проверка этапа 2: советчик предлагает исследования на
собранном наборе, отчёт считается. Это проверяют `web/tests/test_surveys.py`
(25 тестов), `web/tests/test_survey_dataset.py` (10 тестов) и ручной прогон из
раздела «Как проверить руками».

Сайт начинается с главной: рассказ о платформе и два пути — «Создать опрос» или
«Исследовать данные». Рабочее место живёт на `/app`, публичная анкета — на
`/s/<slug>`; на главную можно вернуться из панели и с экрана входа.

## Что умеет этап 1

| Возможность | Где |
|---|---|
| Список «Мои опросы» со статусом и числом ответов | раздел «Опросы» в панели |
| Конструктор: название, описание, настройки, вопросы, порядок, предпросмотр | `/api/surveys`, `SurveysView.tsx` |
| Пять типов вопросов: один вариант, несколько, число, шкала, текст | `surveys.py` |
| Публикация, закрытие и возврат в черновик | `POST /api/surveys/{id}/status` |
| Публичная форма по ссылке `/s/<slug>` без входа | `PublicForm.tsx` |
| Сохранение ответов в таблицах `responses` / `answers` | `POST /api/public/surveys/{slug}/responses` |
| Список сохранённых ответов владельцу | `GET /api/surveys/{id}/responses` |

## Что умеет этап 2

| Возможность | Где |
|---|---|
| Кнопка «Исследовать в Winnow» на экране опроса | `SurveysView.tsx` |
| Сборка набора из ответов движком | `survey_dataset.py` |
| Правильные метки и уровни измерения без догадок | там же |
| Множественные ответы сразу как отметки 1/0 | там же |
| Пересборка того же набора при новых ответах | `POST /api/surveys/{id}/dataset` |

Набор собирается в памяти и сохраняется как обычный набор (`Dataset` + файл
`.winnow`), поэтому дальше работают советчик, 11 процедур, разбиение по
группам, графики и выгрузки в Word/Excel/CSV.


## Решения

Взяты умолчания Google Forms, как договорились.

| Вопрос из плана | Решение | Где видно |
|---|---|---|
| Кто может заполнять | любой по ссылке, без входа | публичные эндпоинты `/api/public/...` |
| Сколько ответов с человека | один с браузера; повторы включаются настройкой `allow_multiple` | cookie `winnow_respondent` |
| Анонимно или с аккаунтом | анонимно: ни аккаунта, ни адреса, ни IP не сохраняется | `responses.respondent_token`, `responses.meta` |
| Защита | случайный `slug`, ограничение частоты, закрытие опроса | `surveys.py`, `WINNOW_SURVEY_RATE` |
| Отдельный сервис | нет: один FastAPI, один вход | `src/winnow/web` |

Что это значит на практике:

* **IP не хранится.** Для ограничения частоты адрес клиента используется как
  ключ счётчика в памяти и никуда не записывается. Поэтому в `responses` нет
  колонки с адресом — только случайный номер браузера.
* **Один ответ на браузер, а не на человека.** Cookie можно почистить и ответить
  снова; это ограничение честно названо в интерфейсе и в README. Полноценная
  защита от накрутки — этап 3 (проверка по нескольким признакам).
* **Черновик не открывается по ссылке.** Пока опрос в статусе `draft`,
  `/api/public/surveys/{slug}` отвечает 404: показывать людям нечего.

## Модель данных

```
Survey          id, owner_id, title, description, status(draft/open/closed),
                slug, created_at, closes_at, allow_multiple
Question        id, survey_id, position, kind, text, required, options(json)
Response        id, survey_id, submitted_at, respondent_token, meta(json)
Answer          id, response_id, question_id, value_text, value_number, option_ids(json)
```

Таблицы называются `surveys`, `questions`, `responses`, `answers`. Класс
`Response` в коде назван `SurveyResponse`, чтобы не путаться с HTTP-ответом
FastAPI; таблица при этом называется так же, как в плане.

`options` — JSON под конкретный тип:

| Тип | `options` | Куда попадёт в наборе (этап 2) |
|---|---|---|
| `single` | `{"choices": [{"id": "1", "label": "Мужской"}, …]}` | категория с метками вариантов |
| `multi` | то же | отметки 1/0 по каждому варианту |
| `number` | `{"min": 14, "max": 100}` | числовая переменная, шкала |
| `scale` | `{"min": 1, "max": 5}` | порядковая переменная |
| `text` | `{"max_length": 2000}` | строковая переменная |

Номера вариантов короткие («1», «2»): ответ хранит именно их, а метка берётся из
вопроса при показе. Поэтому переименование варианта не ломает уже собранные
ответы, а этап 2 отличит вариант от варианта без разбора текста.

## Этап 2: как ответы становятся набором

Имя переменной — **текст вопроса**: в «Данных» сразу видно, о чём столбец, а не
«q3». Метка переменной совпадает с именем, поэтому отчёты не дублируют текст.
Два одинаковых вопроса получают номер: «Да или нет?» и «Да или нет? (2)».

| Вопрос | Переменные | Тип | Уровень |
|---|---|---|---|
| один вариант | «Ваш пол» | числовая, метки вариантов (1 = «Мужской») | номинальная |
| несколько вариантов | «Источники: Радио», «Источники: ТВ», … | числовая, значения 1/0 | номинальная |
| число | «Возраст» | числовая | количественная |
| шкала | «Оцените курс» | числовая | порядковая |
| текст | «Что улучшить» | строковая | номинальная |

Что важно в сборке:

* **пропуск остаётся пропуском.** Если человек не отвечал на вопрос, значения нет
  (NaN), а не ноль. Для множественного выбора это принципиально: «не спрашивали»
  и «не выбрал» — разные вещи, и доли по вариантам поехали бы, если их смешать;
* **никаких догадок.** Движок не угадывает уровни измерения по значениям: они
  берутся из типа вопроса. Это и было целью всей затеи — то, из-за чего при
  загрузке чужого CSV появляются предупреждения советчика;
* **ответы не копируются вручную.** Набор собирается из строк базы при нажатии
  кнопки; в «Данных» не появляется копий «Опрос: …». Повторное нажатие
  пересобирает тот же набор (та же запись, тот же файл), потому что ответы
  приходят и после первого сбора. Правки, сделанные в наборе вручную, при
  пересборке заменяются свежими ответами: источник здесь опрос;
* **ссылка снимается при удалении набора.** Если удалить набор в «Данных»,
  следующее нажатие кнопки соберёт его заново, а не упадёт с ошибкой;
* **в выгрузке SPSS имена латинские.** SPSS не принимает русские буквы в имени
  переменной, поэтому при скачивании в `.sav` имя транслитерируется
  («Ваш пол» → `Vash_pol`, до 64 байт, повторы нумеруются), а полный текст
  остаётся в метке — её SPSS и показывает в отчётах. CSV и Excel сохраняют
  русские имена как есть.

## API

Владелец (нужен вход):

| Метод | Что делает |
|---|---|
| `GET /api/surveys` | мои опросы со счётчиком ответов |
| `POST /api/surveys` | создать черновик (название, вопросы, настройки) |
| `GET /api/surveys/{id}` | опрос с вопросами и признаком `can_edit` |
| `PUT /api/surveys/{id}` | сохранить конструктор целиком |
| `POST /api/surveys/{id}/status` | `draft`, `open` или `closed` |
| `GET /api/surveys/{id}/responses` | сохранённые ответы (последние сверху) |
| `POST /api/surveys/{id}/dataset` | собрать набор из ответов («Исследовать в Winnow») |
| `DELETE /api/surveys/{id}` | удалить опрос без ответов |

Публичная часть (входа нет):

| Метод | Что делает |
|---|---|
| `GET /api/public/surveys/{slug}` | анкета для заполнения + `already_answered` |
| `POST /api/public/surveys/{slug}/responses` | принять ответ, вернуть `201` |

Коды ошибок публичной части:

| Код | Когда |
|---|---|
| `404` | опроса нет или он ещё черновик |
| `403` | опрос закрыт |
| `429` | слишком много ответов подряд с одного адреса |
| `409` | этот браузер уже отвечал, а повторы запрещены |
| `422` | ответ не прошёл проверку: текст ошибки называет вопрос |

## Защита

1. **Случайная ссылка.** `slug` — 8 случайных байт в base64url (11 символов),
   уникальный индекс в базе. Перебрать такие адреса, чтобы найти чужой опрос,
   нереально.
2. **Ограничение частоты.** Скользящее окно на адрес клиента + адрес опроса:
   `WINNOW_SURVEY_RATE` ответов в час (по умолчанию 30). Счётчик живёт в
   памяти процесса; сам адрес не сохраняется.
3. **Один ответ на браузер.** Случайный номер в cookie `winnow_respondent`
   (год жизни, `httponly`, `samesite=lax`). При `allow_multiple=false` второй
   ответ с тем же номером не принимается — 409.
4. **Закрытие.** Вручную (`status=closed`) или по дате `closes_at`. Просроченный
   опрос считается закрытым, даже если статус в базе не меняли: дата — правило,
   а не действие человека.
5. **Зафиксированная структура.** После первого ответа `PUT` отвечает 409.
   Изменять можно только статус. Иначе старые ответы потеряли бы смысл.
6. **Опрос с ответами не удаляется.** `DELETE` отвечает 409: это чужие
   заполненные анкеты.

## Как проверить руками

```powershell
# 1. сервер
web\run.cmd

# 2. интерфейс
web\open.cmd
```

Дальше: открыть сайт (`http://127.0.0.1:8000/`) → на главной выбрать
**«Создать опрос»** → зарегистрироваться → «Создать опрос» → добавить вопросы →
«Опубликовать» → «Открыть» рядом со ссылкой → заполнить в новой вкладке →
«Отправить» → вернуться в конструктор. Внизу появится «1 ответ», кнопка
«Показать ответы» покажет, что именно сохранено, а **«Исследовать в Winnow»**
соберёт из ответов набор и откроет его в «Данных» — с таблицей, переменными,
советчиком и процедурами.

То же без браузера — 35 тестов API по опросам:

```powershell
$env:PYTHONPATH = "src"
web\.venv\Scripts\python -m pytest web\tests\test_surveys.py web\tests\test_survey_dataset.py -q
```
