# Statistical Quality Inspector

Проверка данных и линейной модели перед тем, как верить результатам. Инспектор
ничего не исправляет: он показывает, где именно числам нужна оговорка, и даёт
числа для проверки.

## Что проверяется

### Данные

| Проверка | Уровень | Что означает |
|---|---|---|
| Пустая переменная | критично | все значения пропущены — анализировать нечего |
| Повторяющийся идентификатор | критично | один и тот же случай входит несколько раз |
| Постоянная переменная | предупреждение | не различает группы, только занимает место |
| Много пропусков (≥ 30 %) | предупреждение | вывод опирается на меньшую выборку |
| Заметные пропуски (10–30 %) | заметка | стоит проверить, не связан ли пропуск с группой |
| Полные дубли строк | предупреждение / заметка | искажают N и стандартные ошибки |
| Выбросы по IQR (≥ 5 % значений) | предупреждение | ошибка ввода или реальный разброс — решает человек |
| Дисбаланс групп (< 5 % в группе) | предупреждение | сравнение групп будет неустойчивым |
| Количественная с малым числом значений | заметка | возможно, объявлен не тот уровень измерения |
| Сильная корреляция (|r| ≥ 0,9) | заметка / предупреждение | переменные почти дублируют друг друга |
| Многомерные выбросы (Махаланобис) | заметка / предупреждение | необычное сочетание значений; смотреть строки |

### Линейная модель

| Проверка | Уровень | Что означает |
|---|---|---|
| VIF ≥ 10 (5–10 — заметка) | предупреждение | мультиколлинеарность, коэффициенты неустойчивы |
| Бреуш-Пеган, p < 0,05 | предупреждение | гетероскедастичность: стандартные ошибки неверны |
| Дарбин-Уотсон вне 1,5–2,5 | предупреждение | автокорреляция остатков |
| Влиятельные наблюдения (Кук) | предупреждение | одна-две строки могут определять коэффициенты |
| Остатки не нормальны (Шапиро, p < 0,05) | заметка | на больших выборках влияет мало |
| Меньше 10 наблюдений на предиктор | предупреждение | модели не хватает данных |

## Где в интерфейсе

Вкладка **«Качество»** в наборе данных:

1. «Проверить данные» — только пропуски, дубликаты, выбросы, группы, корреляции.
2. Выберите зависимую переменную и нажмите «Проверить модель» — добавятся VIF,
   Бреуш-Пеган, Дарбин-Уотсон, Кук и нормальность остатков.

Предикторы для модели подставляются из количественных показателей; если их
нет — из остальных числовых переменных. Ничего не сохраняется и не меняется.

## API

```
POST /api/datasets/{id}/quality
Content-Type: application/json

{"target": "y", "predictors": ["x1", "x2"]}
```

`target` необязателен: без него проверяются только данные. Ответ:

```json
{"report": {
  "n_cases": 213, "n_variables": 21,
  "missing_share": 0.04, "duplicate_rows": 0,
  "counts": {"critical": 0, "warning": 1, "note": 2},
  "issues": [{"code": "multicollinearity", "severity": "warning", ...}],
  "variables": [...], "regression": {...}
}}
```

## В агенте

Инструмент `check_quality` принимает `target` и `predictors`, сохраняет расчёт
как `analysis_run` (`procedure = "quality"`) и возвращает модели сводку,
проблемы и диагностику модели. Поэтому ИИ не придумывает «данные грязные» —
он опирается на посчитанные числа и может сослаться на `run_id`.

## Ограничения

- проверки классические и предполагают независимые наблюдения; панельные данные,
  временные ряды и сложные дизайны требуют отдельных методов;
- веса случаев пока не учитываются;
- логистическая регрессия не диагностируется (VIF и остатки считаются для
  линейной);
- инспектор не исправляет данные и не выбирает модель за человека;
- множественные проверки не корректируются: это скрининг, а не итоговый тест.
